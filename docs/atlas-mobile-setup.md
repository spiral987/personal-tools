# スマホで使い始める手順

2026-11-01。Vercel Hobbyで公開済みです。普段使う入口は **[https://personal-tools-seven-ruby.vercel.app/](https://personal-tools-seven-ruby.vercel.app/)**。PCとGalaxyの両方で、このURLを使ってください。Supabaseのメールログイン戻り先は本人から2項目とも設定完了の報告を受けました。実際のメールログインとGalaxy実機の確認は残っています。

すでに金庫がある場合は、新しい金庫を作る前に、下記の「既存データを公開URLへ持っていく」を確認してください。ローカルURLの記録は自動では移りません。

## 公開する構成

Vercelの4プロジェクトを使い、Recallを入口として他の3ツールへ転送します。入口の `/` は `/atlas/` に移動します。4ツールとも入口の同じHTTPS URLを使います。子プロジェクト単独のURLでは別のブラウザ保存領域になり、データや解錠保持を共有しません。PCの常時起動や独自ドメイン購入は不要です。

設定値は `deploy/vercel-projects.json`、実際のプロジェクトID・本番ホスト・ビルドIDは `deploy/vercel-deployment-2026-11-01.json`。Atlas・Collect・Sketchbookの確認済み本番ビルドを先に反映し、入口の `ATLAS_ORIGIN`、`COLLECT_ORIGIN`、`SKETCHBOOK_ORIGIN` に各本番ホストを設定しました。4プロジェクトには同じSupabaseの公開用URLとpublishable keyだけを本番用に設定し、service_role鍵・AI鍵・ワーカー設定は渡していません。

Next.js、Node 22、各アプリのRoot Directory、外側の共通パッケージ参照を有効にし、ルートのpackageManagerに固定されたpnpmでインストールします。ソース配布の準備は `node scripts/prepare-vercel-source.mjs`。環境ファイル、作業ログ、ブラウザプロファイル、node_modulesを含めません。公開用スナップショットをアップロードするため、Gitの未コミット変更を勝手にpushする必要はありません。

[SupabaseのURL設定](https://supabase.com/dashboard/project/zdixgamfhdgnqbgjckpj/auth/url-configuration)へ登録する値は次のとおりです。本人から、2項目とも設定完了の報告を受けました。

- Site URL：`https://personal-tools-seven-ruby.vercel.app`
- Redirect URLsへ追加：`https://personal-tools-seven-ruby.vercel.app/recall/auth/callback/`

既存のローカルcallback許可は残します。子プロジェクトのホストや、広いワイルドカードの許可は不要です。接続ツールにはこの設定の変更機能がなく、本人操作で設定しました。設定後の画面読み戻しはGitHub認証画面へのアクセスが自動承認審査で拒否されたため行っておらず、本人の完了報告に基づく記録です。パスワードや認証コードをチャットへ渡す必要はありません。公開URLからログインメールを送り、同じブラウザで開いて確認します。[Supabase公式の戻り先設定](https://supabase.com/docs/guides/auth/redirect-urls)。

## 既存データを公開URLへ持っていく

PCの `http://127.0.0.1:3100`、`localhost`、公開HTTPS URLは、それぞれ別の保存領域です。公開URLを開くだけではローカルの記録は移りません。先に元のURLでデータが残っていることを確認し、バックアップを取ってください。

クラウド同期済みなら、元のURLで同じアカウントを開き「今すぐ同期」を行い、同期待ち・競合を解消します。公開URLでは**新しい金庫を作らず**、同じメールでログインし、届いたリンクを同じブラウザで開いて既存の金庫を読み込み、これまでの専用パスフレーズで解錠します。

端末内だけの記録なら、元のURLで各ツールの暗号化バックアップを書き出します。公開URLの解錠画面で、そのバックアップから鍵情報を読み込み、同じパスフレーズで解錠してから、各ツールの設定で対応するバックアップを読み込みます。Atlasの整理情報も別に書き出します。バックアップの対象は各画面の案内で確認し、下書きは先に投稿・保存してください。追加読み込みは繰り返すと重複する場合があります。

公開URLで記録・画像・関連を確認してから、必要ならアカウント側へ端末内データを取り込み、同期します。元の保存領域とバックアップは確認が終わるまで消さないでください。

## Galaxyでの確認

1. PCと同じ入口のHTTPS URLをChromeまたはSamsung Internetで開きます。
2. 既存の金庫を使う場合は先に同じメールでログインし、メールリンクを同じブラウザで開きます。メールアプリが別ブラウザで開く場合は、既定ブラウザを合わせて新しいリンクを送ってください。
3. 専用パスフレーズで解錠し、4ツールを移動します。24時間保持を選ぶと、再読込やブラウザ再起動でも同じ期限内は再入力不要です。プライベートモードや保存制限のある環境では短時間ロックを使います。
4. 画像を1枚追加して「収集箱に残す」を押し、同期待ちが解消した後にPCで同じ画像を開きます。逆方向にもテスト用メモを1件保存します。
5. ブラウザのメニューから「ホーム画面に追加」を選びます。通常のURLと同じ金庫・記録が見えることを確認します。
6. 使う各ツールをオンラインで一度開き、オフライン表示の準備が済んでから機内モードにします。保存した記録・下書きを確認し、小さなメモを保存して、オンライン復帰後に同期します。未取得のクラウド画像はオフラインでは開けない場合があります。
7. 手動ロック、24時間の期限超過、別アカウントへの切替も確認します。別の金庫のアカウントは別ブラウザプロファイルで使用します。

公開URLでは、隔離したPCブラウザで新規のテスト用金庫作成、メモと画像原本の保存、4ツールの記録共有、描画下書きの復元、再入力なしの移動、手動ロックを確認しました。4ツールとも初回の準備直後にオフライン再読込でき、画像原本・メモ・描画を復元できました。390px幅の4ツールも確認済みです。実アカウントのログイン、Galaxy実機、ホーム画面追加、実際の2端末同期は未確認です。

## 段階Dへ更新するとき

4ツールの古いタブを閉じて、公開入口を開き直してください。アカウントの金庫を一度開くと、自動整理のために既存の暗号文の期限とファイル参照を端末で確認します。準備が完了してから、期限切れのごみ箱をクラウドでも自動削除します。本文や復号鍵は送りません。端末内モードは次回起動時に期限切れを整理します。[期限・復元・削除範囲](encrypted-vault.md#プロジェクトスペースごみ箱段階d) と [検証記録](atlas-improvement-phase-d-verification-2026-11-01.md)。
