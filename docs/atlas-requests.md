# Atlas要望をCodexへ渡す

RECALLの「保存とバックアップ」にある「Atlas要望をCodexへ」から設定します。金庫を解錠して使います。

1. 「Atlas要望スペースを作る」を押します。すでにある場合は「Atlas要望を共有元に設定」を押します。同名のスペースが複数ある場合は、件数・作成日・IDで共有元を選びます。
2. 改善してほしいことをメモに書き、「Atlas要望」を選んで保存します。1要望につき1メモが目安です。
3. 「保存とバックアップ」から「Atlas要望をCodex向けに書き出す（暗号化なし）」を押します。
4. ダウンロードされた `atlas-requests-YYYY-MM-DD.json` をCodexに添付し、「Atlas要望を全部読んで改善して」と依頼します。

設定しただけではファイル作成や外部送信は行いません。書き出しは解錠済みのRECALL内で実行し、Codexには出力ファイルだけを渡します。金庫のパスフレーズ・復旧鍵は入力しません。

## 共有範囲

共有元のスペースは設定時のIDに固定し、名前で自動的に再検索しません。名前が変わっても同じIDを使い、見つからない場合は出力を拒否します。別の同名スペースが増えても対象は広がりません。

対象はそのスペースに所属する保存済みメモの最新版本文です。1つのメモを他スペースにも置いている場合も、そのメモの本文全体を含みます。所属を外すかごみ箱に移すと、次回の書き出しから外れます。共有元が同じでも下書き・編集中の未保存内容・過去の版・ごみ箱・関連メモ・画像・スケッチ・タグ・プロジェクトは含めません。

書き出し専用形式 `personal-tools.atlas-requests` のメモは `id`・`body`・`updatedAt` の3項目に限定します。金庫の鍵情報、所有者、他スペースの名前や所属、同期履歴、競合版は含めません。RECALLの暗号化バックアップとは別の形式です。

出力ファイルは暗号化されていません。渡した内容はCodexで読めます。共有設定の解除や所属の変更で、すでに作成・添付したファイルの内容を回収することはできません。

## 更新と対応管理

毎回 `mode: "snapshot"` で共有対象の全件を出力します。`shareId` が同じファイル同士で、メモの `id` と `updatedAt`・本文を比較すると追加・変更を把握できます。前回あって今回ないIDは、今回の共有対象から外れたものとして扱います。0件の場合も完全なスナップショットです。以前渡した内容の消去を保証する仕組みではありません。

共有設定は現在の端末・ノートごとに、暗号化された端末DBに保存します。スペースとメモは通常どおり同期しますが、共有設定は同期やバックアップに含めません。別の端末では共有元を設定し直します。解除後に再設定すると `shareId` が変わるため、別の共有として扱います。異なる `shareId` のファイル同士で共有解除を推定しないでください。

現在の実装は手動のファイル受け渡しです。ロック中の取得、常時監視、自動実行、Codexからのメモ更新は含みません。RECALL内では通常の表示と同様に金庫共通の鍵で復号し、Codexに渡す前に許可した範囲へ絞ります。スペースごとに復号鍵を分離する方式ではありません。
