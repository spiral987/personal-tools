# 暗号化金庫

Recall / Sketchbook / Collect / Atlasは、解錠した端末でのみ本文・画像を復号します。メールログインは同期先の認証、専用パスフレーズは金庫の解錠で、別の役割です。

## 初回設定

1. 古い4ツールのタブを閉じ、更新後のアプリを起動します。`pnpm build` / `pnpm start`。普段使う同じorigin（例：`http://127.0.0.1:3100`）を使ってください。
2. 別端末ですでに金庫を作っている場合は、先に同じメールでログインします。クラウドの鍵情報を読み込んでから解錠します。同じoriginに別の金庫がある場合は上書きしません。
3. 初めての場合は、16文字以上の長い専用パスフレーズを設定します。最低文字数を満たすだけで強度が保証されるわけではありません。推測しにくいランダムな単語の組み合わせなどを使ってください。チャットやサーバーの環境変数には入力しません。
4. 生成された復旧鍵を紙など別の場所に保管して確認します。復旧鍵も金庫を開ける秘密です。暗号化バックアップと同じ場所にまとめないでください。
5. 既存の端末DBを暗号化してから各ツールを開きます。アカウントを開くと、クラウドの既存原本・履歴・競合を暗号化して検証し、移行を完了します。

パスフレーズと復旧鍵を両方なくすと、管理者・メールログイン・Supabaseの秘密鍵でも内容を復元できません。復旧鍵での解錠は初期画面から選べます。パスフレーズの再設定UIは含みません。

## 保存と解錠

- AES-256-GCM / 128ビット認証タグ。暗号化ごとに暗号学的乱数の96ビットnonceを生成します。形式バージョン、金庫ID、保存先、レコードの文脈を認証付き追加データに含めます。
- ランダムな256ビットの金庫鍵を、Argon2id（64 MiB、3回、parallelism 4、ランダム16バイトsalt）由来の別鍵で包みます。復旧鍵は独立の256ビット乱数で、同じ金庫鍵を別途包みます。
- 金庫鍵からHKDF-SHA-256でデータ暗号化鍵とHMAC鍵を用途別に導出します。Web Cryptoの鍵は非抽出設定。生の鍵バッファは取り込み後に上書きします。ただしJavaScript/ブラウザ全体のメモリを完全消去できる保証ではありません。
- 既定では入力成功から24時間、非抽出のAESデータ鍵とHMAC鍵をIndexedDBの専用領域へ保存します。ブラウザの鍵オブジェクトを構造化複製する方式で、平文パスフレーズ・復旧鍵・生の金庫鍵は保存しません。localStorageには秘密ではない失効番号と設定だけを置きます。再読込・ツール移動・ブラウザ再起動で期限を延長しません。鍵の保存に対応しない環境では、解錠画面で短時間ロックを選んでください。
- 端末DBには本文、画像、下書き、同期outbox、競合版、補助情報を暗号化して保存します。ローカルの検索キーもHMACで不透明化します。保存成功は暗号文のネイティブIndexedDB transaction確定後に返します。暗号処理中もtransactionを保ち、失敗時は全体をロールバックします。
- 手動ロック・ログアウト・アカウント変更では、応答する全タブの下書き保存を待ち、失効番号を変更して保存鍵と画面の参照を破棄します。保存失敗時の手動ロック・ログアウトは中止して入力を残します。期限切れ・外部からのアカウント変更では保存を試みた後にロックを優先します。停止・凍結中のタブやOS終了直前の未保存入力までは保証できません。
- 期限はアプリによる制御です。鍵そのものに暗号学的な失効機能はなく、ブラウザが停止中の瞬間には削除できません。期限超過後の復帰・起動時に保持鍵を削除し、開いているページでは1秒ごとに確認します。保存情報をコピーした攻撃者、同じoriginで動く悪意あるスクリプト、OS管理者から鍵を守る保証ではありません。非抽出設定もハードウェア保護を意味しません。
- 設定で従来の短時間ロック（無操作5分・非表示1分）を選べます。この場合、復号鍵は永続化せず、再読込・ツール移動・ブラウザ終了後に再解錠します。設定を変えると下書きを保存して全タブをロックします。共有端末では短時間ロックまたは利用後の手動ロックを選んでください。
- 保持情報はorigin・同期先project・アカウント・金庫の鍵情報に結び付けます。同じブラウザに別の金庫がある場合は上書きせず、別プロファイルで開くよう案内します。アカウントごとの複数金庫を同一originに同居させる機能は含みません。
- 下書きは各ツール・保存先ごとに共有します。未編集の古いタブはロック時に再保存しません。同じツールの複数タブで同時に別々の下書きを編集する場合は、最後の保存が反映されるため、別の内容を書き始める前に原本として保存してください。

## 同期・画像・バックアップ

RECALLの「Atlas要望をCodex向けに書き出す（暗号化なし）」は、明示的に設定したスペースの保存済みメモだけを共有する専用出力です。通常のバックアップとは別で、解錠した端末で暗号化しないJSONを作ります。[共有範囲と使い方](atlas-requests.md)を確認してください。

`vault_keys`は暗号化された鍵情報、`vault_records` / `vault_operations` / `vault_changes`は暗号文と同期に必要な識別子・revisionを扱います。段階D以降は、復号鍵なしで期限削除するため、削除期限・不透明な原本パス・関連先IDも別に保存します。本文・タイトル・タグ・スペースの所属一覧はこの情報に含めません。全テーブルは所有者RLSで保護し、更新は認証を検証するRPCへ限定します。画像はprivateの`personal-tools-vault` bucketへ暗号文として送り、アップロード後に再取得・復号してハッシュを検証します。パスには原本のファイル名や公開SHA-256を使いません。

同期の操作IDは再送に使い、平文の代わりにHMACのcommitmentで操作の同一性を確認します。競合時は端末で双方を復号し、既存の「両方残す」手順で解決できます。

各ツールのバックアップは`personal-tools.encrypted-backup`形式です。鍵情報と暗号文を含み、画像原本も暗号化します。解錠後に読み込めます。新しい端末では、初期画面でバックアップの鍵情報を読み込み、パスフレーズか復旧鍵で開いてから各ツールへ読み込みます。旧平文JSONの追加読み込みは引き続き可能ですが、新しく書き出すバックアップは暗号化されます。Sketchbookの「PNG（暗号化なし）」は共有用の画像出力で、金庫外へ通常の画像ファイルを作ります。各ツールのバックアップ対象範囲は従来どおりで、全端末DB・全履歴の一括バックアップではありません。

クラウド側はID・種類・操作順・件数・暗号文の長さ、認証サービスはメールアドレス等を知り得ます。これらまで隠す匿名通信の仕組みではありません。悪意あるサーバーによる履歴の巻き戻しや欠落を完全に検出する仕組みも含みません。

## 既存データの移行

追加migrationは`20261031082941_encrypted_vault.sql`。既存migrationは変更していません。

端末はIndexedDB v6に移行し、古い接続を閉じてから、DBごとに元データを暗号文へatomicに置き換えます。鍵の異なるDBや破損した暗号文を平文として開くフォールバックはありません。

クラウドは、初回解錠・ログイン後に次の順序で移行します。

1. 暗号化された鍵情報を登録して、旧平文の同期・登録・AI設定・アップロードを停止。
2. 所有者の原本、所属、過去の同期履歴、競合を読み、暗号化アーカイブを保存して再取得・復号・照合。
3. 端末の未送信編集を保持し、新しい暗号化同期へ投入。画像原本も暗号化して検証。
4. 暗号化同期の確定後、旧StorageファイルをSDKで削除。アーカイブ件数と旧ファイルの残存をSQLで検証し、現在の旧平文テーブルを同一transactionで削除。

中断時には再試行でき、アーカイブや画像の検証に失敗した状態で旧原本を削除しません。移行元が残っている場合はエラーを表示します。参照先のない旧Storageファイルがあれば完了を拒否します。移行履歴の暗号化アーカイブはクラウドに保持し、通常の検索対象や各ツールのバックアップには含めません。

**既存データは、初回設定と移行が完了するまでは従来の保存状態です。** 過去に作った平文JSON、ブラウザやOSのバックアップ、ディスクの削除済み領域、SupabaseのバックアップやWALから過去の平文を消すことまでは保証しません。

## 検索と外部通信

通常の日本語検索・絞り込みは端末内の復号データで継続します。外部AI APIとURLメタデータ取得APIは410を返し、画面からの送信も停止しています。AIワーカーのCLI起動も停止します。ローカルAIは今回追加していません。

GETのPWA Share Targetも私有テキストがURL・サーバーリクエスト・履歴へ入るため登録しません。URLは解錠後に貼り付け、画像は選択してください。旧共有URLで開いた場合は、起動時に共有パラメータを画面の履歴から除き、ページのメモリ内でだけ引き継ぎます。過去の閲覧履歴を消すことはできません。

公開shellのservice worker cacheを更新し、Referrer-Policy / nosniff / frame拒否 / object・base制限を4アプリへ付けています。端末感染、悪意あるブラウザ拡張、改ざんされたアプリが解錠時に実行される状況では、暗号化だけで平文やパスフレーズを守れません。OSのディスク暗号化・画面ロックも併用してください。

## 検証

`pnpm test`は実際の暗号化を有効にして既存試験を実行します。追加試験では改ざん・文脈差し替え・誤パスフレーズ、復旧鍵、IDB内の暗号文、画像原本、ロック前の下書き保存、RLS、再送・競合、移行中断と再開を確認します。PGliteはmigrationの実SQLを実行しますが、Supabase Auth/Storageのscaffoldは試験用です。暗号ライブラリの利用を含むこのアプリ全体への第三者暗号監査を実施したという意味ではありません。

設計資料：[Web Crypto AES-GCM](https://developer.mozilla.org/en-US/docs/Web/API/SubtleCrypto/encrypt)、[Argon2 RFC 9106](https://www.rfc-editor.org/rfc/rfc9106.html)、[hash-wasm](https://github.com/Daninet/hash-wasm)、[Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security)。

## プロジェクト・スペース・ごみ箱（段階D）

4ツールで同じAtlasプロジェクトを使い、一覧・絞り込み・所属を変更できます。各ツールの設定からスペースを削除すると、そのIDの所属だけを保存済み記録と下書きから外します。原本・ほかのスペース・タグ・プロジェクトは残ります。Atlas要望の共有元を削除した場合は共有が無効になり、同名スペースへ自動では切り替えません。

ごみ箱の期限は、日本時間で翌月の同日時です。同じ日がない月は月末に丸めます。期限前の復元で取り消し、再度ごみ箱へ入れると新しい期限に変わります。期限後の更新・復元は拒否します。端末内モードは次回起動時、開いている間は定期的に整理します。

アカウントの初回更新では、古いタブを閉じて更新したアプリを一度解錠してください。既存の暗号文・履歴・移行アーカイブを端末で確認し、削除期限とファイル参照の索引を準備してから自動削除を有効にします。途中で通信が切れても再開できます。鍵や本文はサーバーへ送りません。準備完了までは古いデータの自動削除を始めません。

クラウドは10分ごとの定期処理で、期限切れの本文の暗号文・履歴・競合版・該当アーカイブを削除します。ファイルは共有参照がなくなった後、10分の待機期間を置き、Storage APIで実データを削除します。期限到達とファイルの物理削除は同時ではなく、通常は数十分程度の時間差があり、件数や通信・サービスの休止によってさらに遅れる場合があります。削除通知と内容を含まない再送確認情報は残し、古い端末の再接続による復活を防ぎます。

別端末で期限前に復元されていた可能性があるため、オフライン端末だけの判定でクラウド原本を消しません。サーバーの最新状態を確認して削除を確定します。別端末での復元に備え、画像の暗号化キャッシュは確定通知の受信まで保持し、その後に整理します。Supabaseの休止・障害中は処理できません。提供元のバックアップ・ログの保持、手動出力済みのバックアップや画像の消去は別です。Drive原本には接続していません。
